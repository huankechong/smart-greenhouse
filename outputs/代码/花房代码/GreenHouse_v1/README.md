## 使用节奏（对照 30 天计划）

| 周 | 操作 |
|---|---|
| W1 到货 | 全开关保持 0，直接烧录 → 串口 115200 看土壤/光照 raw 读数 → 实测后改 `SOIL_RAW_DRY / SOIL_RAW_WET` 两个标定值 |
| W1-D5 | 接好 DHT11(41号) 和 OLED(25号) → `EN_DHT=1`、`EN_OLED=1` → 编译烧录 |
| W2 | 接好继电器(16号)+水泵 → `EN_WATER=1`（**先空载试，蓄水瓶不接水路**）；继电器若低电平触发，把 `RELAY_ACTIVE_HIGH` 改 0 |
| W2+ / W3 | 接水位检测（**P52 浮球开关干接点**，第 10 件替换盖中心孔穿出，GPIO32）→ `EN_LEVEL=1` → 万用表确认 `LEVEL_WET_CLOSED` 极性后编译 |
| W3 | `EN_WIFI=1` + 填 WiFi 名密码（手机 2.4G 热点）→ `EN_MQTT=1` + 填巴法云 UID → `EN_WEB=1` |

## 浇水控制逻辑（四档，答辩就讲这张）

### 一、自动档：缺水才浇，浇完必复测

```
        ┌───────────────┐  土壤% < 35          ┌──────────────┐
        │ 0 监视        │ ───────────────────► │ 1 浇水中     │
        │ 每 5s 采样    │                      │ 继电器吸合   │
        └───────────────┘                      │ 3 秒后断开   │
                ▲                              └──────┬───────┘
                │ 湿度 ≥ 35%                          │
        ┌───────┴───────┐                             ▼
        │ 2 停水复测    │ ◄───────────────────────────┘
        │ 等 30 秒再读  │
        └───────┬───────┘
                │ 仍 < 35%，且本轮未满 6 轮 → 回 1（轮数 +1）
                │ 已连浇 6 轮仍 < 35%
                ▼
        ┌────────────────────┐  停 10 分钟（红快闪）  ┌────────────────┐
        │ 4 冷却保护         │ ─────────────────────► │ 回 0，计数清零 │
        │ 判定传感器异常     │                        └────────────────┘
        └────────────────────┘
```

**为什么是"3 秒 + 30 秒"而不是一次浇够**：一次浇狠了水会顺着盆底孔直接漏掉，根还没吸到；30 秒是让水在土里扩散、传感器读数稳定下来的时间，复测才是"浇到位没有"的真判据。这也是答辩里"闭环控制"的实证。

**为什么最后要有个"冷却"**（v1.2 加、v1.5 修复后真正生效）：如果土壤传感器脱土、排线松了、或探头被土裹住读不出变化，单靠"仍干就再浇"会变成每 33 秒浇一次、无限浇下去——水箱抽干、盆泡烂。连浇 6 轮（合计 18 秒水）仍判缺水，基本可以断定"不是土干，是读数不对"，于是停手 10 分钟、红灯快闪让人来看一眼。

> ⚠️ **v1.5 修掉了这个保护的一个致命缺口**：原实现里"再浇"分支没有给连浇轮数加一，轮数恒为 1，导致 6 轮上限永远不触发——保护写了但从未生效。现已修复，状态机模拟验证第 6 轮必进冷却。

### 二、远程档：巴法云发 on，浇 5 秒

```
手机小程序 → 巴法云主题 4QT4BZIBM001 发 "on"（大小写均识别，v1.5 起）
  → MQTT 回调 → waterState=3（手动浇水中，5 秒）
  → 非阻塞实现：这 5 秒里 OLED/MQTT/网页照常响应
  → 浇完自动回 off，防止服务器残留消息重复触发
```

### 三、兜底档：断外网也能看

`EN_WEB=1` 时 esp32 自己开 HTTP 服务（局域网 IP 访问），不依赖巴法云。这是"断网兜底"，答辩现场 WiFi 挂了也能演示。**只读，无控制端点。**

### 四、水位保护：低水位拒启、拒手动、浇中即停（v1.5.1 全覆盖；v1.6 修正消抖计数）

`EN_LEVEL=1` 时按 `waterState∈{1,2,3}` 判定——自动浇水中、停水复测窗口、远程手动浇水**三种状态全覆盖**：水位低 → 立即断泵并复位状态机。首版实现误用继电器电平门控，在复测窗口（状态 2）成为死代码，v1.5.1 已改为按状态判定并用四场景模拟验证。v1.6 顺带修正消抖计数（原 `>= N-1` 实际只等 2 次即 200ms，与注释不符，现按 `>= N` 真等 3 次）。

### 关键参数（都在 `GreenHouse_v1.ino` 顶部，改数字不用改逻辑）

| 参数 | 当前值 | 含义 |
|---|---|---|
| `SOIL_THRESHOLD_PCT` | 35 | 低于 35% 判缺水（**拍脑袋初值，需实测标定**） |
| `SOIL_RAW_DRY` / `SOIL_RAW_WET` | 3200 / 1300 | 干/湿两点的 raw 读数，映射成 0–100% |
| `WATER_MS` | 3000 | 每轮浇水 3 秒 |
| `SETTLE_MS` | 30000 | 浇完停 30 秒再复测 |
| `MANUAL_WATER_MS` | 5000 | 远程手动浇水 5 秒 |
| `MAX_ROUNDS_PER_CYCLE` | **6** | 一个处理周期最多连浇 6 轮（=18 秒水），到顶转冷却 |
| `COOLDOWN_MS` | **600000** | 冷却 10 分钟，之后计数清零重新监测 |
| `LEVEL_WET_CLOSED` | **true** | true=有水时触点闭合（常开型），**万用表实测确认后可改** |
| `LEVEL_STABLE_N` | 3 | 连续 3 次一致才认（水面波动会抖） |
| `SENSOR_INTERVAL_MS` | 5000 | 采样周期 |
| `EN_WATER` | **0** | 总闸：0=只读不浇，接线确认后再改 1 |
| `EN_LEVEL` | **0** | 水位检测开关：接好浮球开关再开 |

> 标定值有三道 setup 自检：超 0–4095 量程报错（v1.5 加）；干湿差 <800 报警噪声过敏（v1.5 加）；填反检测（v1.1 已有）。**v1.6 起标定非法不再只警告，而是 setup 硬停机**（红灯快闪挂起、不进 loop），杜绝带错标定进入自动浇水；同时 `safeMap()` 防除零——即使两标定值填成相等，也返回 100（最湿→判不缺水）的 fail-safe 值，不再 panic 重启。

### 状态灯语义（现场一眼判断，答辩也可讲）

| 灯 | 含义 |
|---|---|
| 绿灯常亮 | 湿度正常 |
| 红灯常亮 | 缺水（但还没到浇水条件，如水位低） |
| 红灯 300ms 闪 | 正在浇水 |
| **红灯 100ms 快闪** | **冷却保护**（连浇 6 轮未恢复，疑似传感器异常） |
| 红灯 1s 慢闪 | 水位过低，暂停浇水 |

## 上传排障

报 `not responding / not in sync`：按住板上 **BOOT** 键点上传，出现 `Connecting....` 后松开。

## 已知限制（答辩时如实讲）

- 巴法云 9501 为 TCP 明文 MQTT，clientID 即 UID，无独立认证——知道主题名 + UID 即可下发指令。风险可接受（只驱动 3V 小水泵，无锁/加热），但**答辩后应到巴法云控制台重置 UID**。
- 局域网网页服务无鉴权。当前**只输出数值、只读**，无 XSS 面；若日后加控制端点，必须先加 `server.authenticate()`。
- 雨滴探测模块已取消借用；水位检测定版 P52 浮球开关（干接点，接线见《花房接线规划表》第 8 节）。
