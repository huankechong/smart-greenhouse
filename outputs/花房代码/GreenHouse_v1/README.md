## 使用节奏（对照 30 天计划）

| 周 | 操作 |
|---|---|
| W1 到货 | 全开关保持 0，直接烧录 → 串口 115200 看土壤/光照 raw 读数 → 实测后改 `SOIL_RAW_DRY / SOIL_RAW_WET` 两个标定值 |
| W1-D5 | 接好 DHT11(41号) 和 OLED(25号) → `EN_DHT=1`、`EN_OLED=1` → 编译烧录 |
| W2 | 接好继电器(16号)+水泵 → `EN_WATER=1`（**先空载试，蓄水瓶不接水路**）；继电器若低电平触发，把 `RELAY_ACTIVE_HIGH` 改 0 |
| W2+ / W3 | 接水位检测（26号雨滴模块或浮球开关，`PIN_RAIN=32`）→ `EN_LEVEL=1` → 实测 `LEVEL_DRY_RAW` 后编译 |
| W3 | `EN_WIFI=1` + 填 WiFi 名密码（手机 2.4G 热点）→ `EN_MQTT=1` + 填巴法云 UID → `EN_WEB=1` |

## 浇水控制逻辑（三档，答辩就讲这张）

### 一、自动档：缺水才浇，浇完必复测

```
        ┌───────────────┐  土壤% < 35          ┌──────────────┐
        │ 0 监视        │ ───────────────────► │ 1 浇水中     │
        │ 每 5s 采样    │                      │ 继电器吸合   │
        └───────────────┘                      │ 3 秒后断开   │
                ▲                              └──────┬───────┘
                │ 湿度 ≥ 35%                          │
        ┌───────┴───────┐                             ▼
        │ 2 停水复测    │ ◄───────────────────────────┘
        │ 等 30 秒再读  │
        └───────┬───────┘
                │ 仍 < 35%，且本轮未满 6 轮 → 回 1
                │ 已连浇 6 轮仍 < 35%（v1.2）
                ▼
        ┌────────────────────┐  停 10 分钟（红快闪）  ┌────────────────┐
        │ 4 冷却保护         │ ─────────────────────► │ 回 0，计数清零 │
        │ 判定传感器异常     │                        └────────────────┘
        └────────────────────┘
```

**为什么是"3 秒 + 30 秒"而不是一次浇够**：一次浇狠了水会顺着盆底孔直接漏掉，根还没吸到；30 秒是让水在土里扩散、传感器读数稳定下来的时间，复测才是"浇到位没有"的真判据。这也是答辩里"闭环控制"的实证。

**为什么最后要有个"冷却"**（v1.2 加）：如果土壤传感器脱土、排线松了、或探头被土裹住读不出变化，单靠"仍干就再浇"会变成每 33 秒浇一次、无限浇下去——水箱抽干、盆泡烂。连浇 6 轮（合计 18 秒水）仍判缺水，基本可以断定"不是土干，是读数不对"，于是停手 10 分钟、红灯快闪让人来看一眼。

### 二、远程档：巴法云发 on，浇 5 秒

```
手机小程序 → 巴法云主题 4QT4BZIBM001 发 "on"
  → MQTT 回调 → waterState=3（手动浇水中，5 秒）
  → 非阻塞实现：这 5 秒里 OLED/MQTT/网页照常响应
  → 浇完自动回 off，防止服务器残留消息重复触发
```

### 三、兜底档：断外网也能看

`EN_WEB=1` 时 esp32 自己开 HTTP 服务（局域网 IP 访问），不依赖巴法云。这是"断网兜底"，答辩现场 WiFi 挂了也能演示。

### 关键参数（都在 `GreenHouse_v1.ino` 顶部，改数字不用改逻辑）

| 参数 | 当前值 | 含义 |
|---|---|---|
| `SOIL_THRESHOLD_PCT` | 35 | 低于 35% 判缺水（**拍脑袋初值，需实测标定**） |
| `SOIL_RAW_DRY` / `SOIL_RAW_WET` | 3200 / 1300 | 干/湿两点的 raw 读数，映射成 0–100% |
| `WATER_MS` | 3000 | 每轮浇水 3 秒 |
| `SETTLE_MS` | 30000 | 浇完停 30 秒再复测 |
| `MANUAL_WATER_MS` | 5000 | 远程手动浇水 5 秒 |
| `MAX_ROUNDS_PER_CYCLE` | **6** | 一个处理周期最多连浇 6 轮（=18 秒水），到顶转冷却 |
| `COOLDOWN_MS` | **600000** | 冷却 10 分钟，之后计数清零重新监测 |
| `LEVEL_DRY_RAW` | **2500** | 水位检测 raw 高于此值判"没水"（**需实测标定**） |
| `SENSOR_INTERVAL_MS` | 5000 | 采样周期 |
| `EN_WATER` | **0** | 总闸：0=只读不浇，接线确认后再改 1 |
| `EN_LEVEL` | **0** | 水位检测开关：接好传感器再开 |

### 状态灯语义（现场一眼判断，答辩也可讲）

| 灯 | 含义 |
|---|---|
| 绿灯常亮 | 湿度正常 |
| 红灯常亮 | 缺水（但还没到浇水条件，如水位低） |
| 红灯 300ms 闪 | 正在浇水 |
| **红灯 100ms 快闪** | **v1.2 冷却保护**（连浇 6 轮未恢复，疑似传感器异常） |
| 红灯 1s 慢闪 | v1.2 水位过低，暂停浇水 |

### v1.2 已补的两条保护

1. **连浇上限 + 冷却**：见上面状态机状态 4。串口会打 `[保护] 已连浇 6 轮仍判缺水 —— 传感器可能脱土/线松/故障`，同时上报云端 `状态#冷却保护`。
2. **低水位停泵**：`EN_LEVEL=1` 时读 `PIN_RAIN`（GPIO32）。水位低 → 拒绝自动启动、拒绝远程手动、浇到一半也会立刻停泵；串口 10 秒一条 `[保护] 水位过低`，云端上报 `水位#低`。

> ⚠️ **两个必须实测确认的点**：
> - **传感器选型**：26 号雨滴模块是**电阻式**（板面裸露铜箔），**隔着塑料瓶壁大概率测不到水位**。可行的三种做法：① 换成 2 元浮球开关（最稳，接 GPIO32 读高低电平）；② 把雨滴板直接浸在瓶内水里（能测，但长期电解会腐蚀，只适合答辩演示）；③ 把电极从瓶口伸进水里。**先实测再定**，`LEVEL_DRY_RAW` 也按实测改。
> - **`LEVEL_DRY_RAW` 极性**：当前假设"干=高 raw"。若你的模块是"有水=高"，把比较改成 `<`，或把阈值反过来设。

## 上传排障

报 `not responding / not in sync`：按住板上 **BOOT** 键点上传，出现 `Connecting....` 后松开。
