# 花房整机示意模型 · 交付说明

> 生成日期 2026-10-18 · 脚本 `build_assembly.py`
> 用途：报告配图 / PPT 页 / 答辩讲"系统长什么样"

---

## 一、这是什么

把三批打印件（P0 三件 + P1/P2 五件 + 底盘三件）**按 1:1 实体尺寸**装到整机底盘上，再补上非打印件（花盆、土、植株、水箱、水泵、面包板、ESP32、继电器、水管、OLED 屏、传感器板），拼成一个完整的系统示意图。

**关键点：装配图里的打印件不是另画的一套**——脚本直接 `import` 了前面三个建模脚本的生成函数，调用的是同一份几何函数，所以模型和送去打印的 STL 完全一致。

### 三·补一、落座高度（与底板 v1.1 对齐）

底板不是平板：花盆/水箱/面包板/继电器各有 1.5–4mm 深的定位槽，件必须**坐进槽底**，否则出现"件浮着、槽空着"的假装配。本版逐件核对过（`check_base_fit.py`）：

| 件 | 底面 z | 依据 |
|---|---|---|
| 花盆 | 2.0 | φ62 凹槽 深 6 |
| 水箱 | 3.0 | **φ108 圆槽** 深 5 |
| 水体 / 水泵座 | **5.0** | 桶内底（3 + 桶底厚 2.0） |
| 水泵 | 7.4 | 座底板 3 之上 |
| 水箱盖 | 124.0 | 裙边下探 6（桶口沿 z=**130** = 槽底3 + 桶高127） |
| 面包板 / 继电器 | 4.5 | 槽 深 3.5 |
| ESP32 | 4.5 起（坐在面包板上，顶 15.5） | 随面包板，无独立槽 |
| OLED 支架 / DHT11 座 / 扎线座 / LED 座圈 | 8.0 | 无槽，坐板面 |
| 连接块 | 4.5 | 沉槽 深 3.5 → **与板面齐平** |

同时发现并修掉：**底板原先给 ESP32 开的 55.6×28.6 槽一直是空的**（ESP32 实际插在面包板上），已在底板 v1.1 删除；**裸 LED 没有安装位**，已补 φ5.2 通孔。

> 底板 **v1.2**（板厚 6→8、连接块齐平）只加深了各槽，**槽底绝对高度一个没动**，所以上表全部不变——只有坐板面的那几件随板顶从 6 抬到 8。

## 三·补、配色规则（v1.5 重配）

初版给了 16 个颜色，结果 4 个近似白、3 个近似黑、3 个同系蓝，图例看着像重复。重配原则：

1. **按材质归并，不按零件逐一分色**——图例从 16 项压到 14 项（取消灯罩后新增裸 LED，现为 **15 项**）：底盘与 2 块连接块合并为一档（现实中都是同一卷白色 PLA），植株的茎与叶合并为一档。
2. **15 个颜色两两色差 ΔE(CIE76) 全部 ≥ 12**，用脚本算过，没有近似对。
3. 色板按功能分四族：打印件（浅冷灰/近白）、植物与土（陶土/深棕/绿）、电控（炭黑/靛蓝/米黄/深绿/近黑蓝）、水系统（浅青/中蓝/岩灰/青绿）——同族用明度拉开，跨族用色相拉开。
4. 颜色单一数据源：`build_assembly.py` 的 `C` 字典，HTML 图例、glb 材质、PNG 渲染全部读它，改一处三处同步。

## 三·补二、细节层 v1.7（2026-10-19）

按"把模型做细"的要求，在不动任何 STL 的前提下给示意模型补了一层零件特征与装配细节。**几何量 24,608 → 33k+ 面，HTML 1.33 → 1.87 MB（现行 34,734 渲染面，AR09 走线优化重出）。**

| 组 | 加了什么 | 面数成本 |
|---|---|---|
| 面包板 | 2×（12×4）孔阵 + 中央沟 + 4 条电源轨（不真打 400 孔，肉眼等价、省 95%） | ~1.2k |
| ESP32 | USB-C 口、两颗按键、PCB 天线（铜色）、金属屏蔽罩 | ~0.1k |
| 继电器 | 3 个绿色接线端子、红色指示灯、光耦 | ~0.1k |
| OLED | FPC 排线、4 针排针、驱动 IC | ~0.1k |
| 土壤传感器 | 两根铜探头、排针 | ~0.1k |
| DHT11 | 正面三道格栅 | ~40 |
| 水泵 | 进水格栅 5 圈、出水嘴 | ~0.2k |
| **螺丝** | **8 颗 M3×6 盘头自攻**（底盘连接块，头面 z=8 与板面齐平） | ~0.5k |
| **跳线** | **20 根**：ESP→OLED 4、ESP→DHT 1、ESP→土壤 3、ESP→继电器 1、继电器→水泵 2、ESP→面包板 5、ESP→LED 2、面包板→继电器 2 | ~7k |

**跳线是校验过的，不是画上去的**：每条线沿途取 8–10 个采样点，对 12 个主要件做奇偶射线法判内外，逐轮修坐标。首版 20 根里 **16 根穿模**，重排后降到 **1 根**（线 05 的端点扎进 DHT 座 0.1 mm——那本来就该"插进去"）。复检脚本见 `check_wires.py`。

### AO（环境光遮蔽）怎么做的

- **烘焙**，不是在 WebGL 里跑 SSAO：每个面沿法线做 12 条余弦半球采样射线，被打到即遮蔽，再做 2 轮邻面平滑。结果缓存到 `ao_cache.npz`（改几何自动失效重算，约 5–7 分钟）。
- **PNG / glb / HTML 共用同一份 AO**，三处颜色一次改全改。
- **分件策略**（踩过的坑）：布尔会把大平面切成大量碎片面，逐面 AO 会在底板上形成"皱纸"斑块，还出现过大面积发黑。最终：结构件（底盘/盆/箱/板）AO 压缩到 **0.80–1.0** 只留微弱层次，细节件（螺丝/排针/跳线/孔阵）保留全强度。

## 四、看图时注意什么

1. **水箱前壁是剖开的**——不是为了好看，是因为真机里水泵在箱底，不剖开看不到。答辩时可以专门说一句"这里做了剖切显示"。
2. **水位画到 20mm**，泵体上半截露在水面上，方便看出"底吸"这个结构特征。
3. **植株是示意**，不是仿真植物形态；叶片位置只保证"不穿模、不压件"。
4. **水管是示意走向**，实际扎带固定点要按你实物走。

## 五、这次装配暴露并修掉的一个真缺陷

把传感器板往支架上一装就发现：**板子进不去土**。

- 原设计板槽是锥形 2.4→1.8，槽底封在 z=8。板厚 1.6，1.8 的窄口永远夹不住它；而封底又让板子顶在 z=8 下不去，传感器头悬在土面上方。
- 已改为**恒定 1.5mm 过盈槽 + 槽贯通底板**：板子压进去靠 PLA 弹性夹住，插入深度任意可调，下端可正常入土。
- P0 的 STL 已重新生成（23.4 g），`交付说明_P0三件v1.md` 的参数表已同步更新。

> 这就是做装配图的价值——单看零件图发现不了装配关系错误。

> 2026-10-18 全量审计（AR02）又在此模型上查出 6 处穿模并修复，详见 `docs/审计报告/AR02_GreenHouse3D模型审计修复报告_2026-10-18.md`。

## 六、已知限制

1. **跳线是示意路径，不是接线图**：走向按"不穿实体 + 不挡屏幕"排的，颜色统一为哑光灰（20 根彩线会糊成一片）。真实接线以《花房接线规划表》为准（真实接线是 18 根杜邦，VCC/GND 走面包板电源轨，与图中 20 根不是一套数）。
2. **AO 在结构件上被压缩**（0.80–1.0）：大平面上放不出真实接触阴影，只能在缝隙和小件上看出层次——这是逐面 AO + 布尔碎片面的物理限制，不是漏做。
3. **花盆、水箱尺寸是占位值**（φ82 口 / 118×90×60），实物不同的话改 `build_assembly.py` 顶部的常量再跑一次。水泵与 ESP32 已按实物实测尺寸建模（泵 41×39×30、ESP32 51.5×28）。
4. **干涉已经查过，不是「允许穿模」**：`audit.py` 会逐对布尔求交。**土壤×传感器挂钩已从 11522 → 0 mm³**（01b v2 去掉长斜臂），现在可以先填土再挂；剩余的两项都是设计意图：土壤×传感器板 1075（板插在土里）、挂钩×传感器板 62.4（槽 1.4 vs 板 1.5 的过盈夹持）。
5. 旧的 `outputs/花房3D概念模型/`（早期概念探索）已于 2026-10-20 删除，历史版本可从 git 记录找回；本目录模型是唯一现行示意。
