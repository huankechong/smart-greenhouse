### 1.3 关键技术决策（可写进 Analysis 的方法论）

| 决策 | 原因 |
|---|---|
| `safeMap` 替代 Arduino `map()` | `map()` 是宏，标定值填反/相等时除零 → panic 重启 |
| 标定非法硬停机 + 红灯快闪 | 防止"警告后继续跑 → 无限重启"难以排查 |
| 继电器电平第一优先锁定 | 必须在任何停机分支之前，否则低电平触发模块误吸合 → 泵空转 |
| 外部 1kΩ 上拉（非内部 45kΩ） | 干簧管有"湿电流"门槛，内部上拉只有 0.07mA，触点氧化后会时通时断 |
| 状态机非阻塞 | 浇水期间 MQTT/Web 照常响应，不用 `delay()` 阻塞 |
| 本地 LittleFS 记录 | 云端免费版无历史数据 API，本地记录独立于网络 |

## 三、技术发现（写 Analysis，**这是报告最有价值的部分**）

### 发现 1：光敏通道暗态饱和（硬件设计缺陷）

| 项 | 数据 |
|---|---|
| 现象 | **夜间（22:00–07:00）光照 raw 恒为 4095**（12 位 ADC 满量程） |
| 白天 | 08:00–11:00 降至 1088–1283（有分辨力） |
| 全窗口占比 | `≥4000` 的样本占 **75.7%**，`=4095` 占 **71.4%** |
| 成因 | 光敏电阻分压电路极性为"光强↑→分压↓"，暗态时电阻极大，分压点被拉满 |
| 影响 | **夜间 10 小时完全无分辨力**，无法区分"全黑"与"微弱光"，光照曲线仅白天有效 |
| 改进 | ① 软件定性（4095 视为暗）② 加大上拉电阻 ③ 换 BH1750 数字传感器（I2C 0x23，与 OLED 0x3C 不冲突） |

### 发现 2：土壤探头无温度补偿（器件特性局限）

| 项 | 数据 |
|---|---|
| 矛盾现象 | 环境气湿从 79% 降到 64%（变干 15 点），土壤读数反而从 69% 升到 77% |
| 同期温度 | 24.0 → 26.9℃（+2.9℃） |
| 成因 | 电容式土壤探头有明显温度系数，未做补偿 |
| 另一局限 | 60–79% 区间可能已接近该探头非线性/饱和段 |
| 影响 | "湿度百分比"只能作**相对干湿指数**，不能当真实体积含水量（VWC） |
| 改进 | 按 Topp 方程逐种土壤标定，或换工业级探头（超预算） |

### 发现 3：ADC 采样尖峰（采集侧并发干扰）

| 项 | 数据 |
|---|---|
| 尖峰次数 | **28 次**（相邻采样 Δ > +10 个百分点，**基于 14.93h 有效段 5,376 条**） |
| 占比 | **0.52%**（28 / 5,375） |
| 自愈率 | 85% 在下一个采样（10 秒）即回落到原位 ±3 内 |
| **关键规律** | **秒位 100% 落在 `:06` 或 `:07`**（28/28 次） |
| 成因推断 | 固定相位的周期性任务冲突 —— 采样瞬间与 WiFi 发射窗口重叠，射频电流冲击导致 ADC 偏差 |
| 影响 | 剔除后均值仅从 71.10 变 71.00，对统计结论无影响 |
| 改进 | 9 点滑动中值滤波（**v1.9 已实现**） |

### 发现 4：传感器失效的排查方法论（可作加分内容）

**故障现象**：土壤读数从 11-20 12:00 起锁死 100%，持续 31.6 小时零波动。

**逐层排除过程**：

| 步骤 | 动作 | 结果 | 结论 |
|---|---|---|---|
| 1 | 观察读数特征 | 14 小时零波动（真实湿度必有 ±1–2% 抖动） | 判定为 ADC 被 `constrain` 夹在端点 |
| 2 | 换备用探头 | 仍为 500–800（异常低） | 排除单个探头故障 |
| 3 | 拔掉 OUT 线测悬空 | 读数仍 500–700 | 悬空漂移值，无法定论 |
| 4 | 三根线直连 ESP32 板（绕过面包板） | **raw 回到 1729–2352（正常）** | ✅ **定位：面包板供电轨接触不良** |
| 5 | 手指捏探头感应区 | raw 明显下降（1158→1428） | 确认探头活性正常 |
| 6 | 探头插回土中 | raw 稳定 1139–1143（72%） | 系统恢复正常 |

**方法论价值**：
> "从读数特征 → 换件 → 绕过中间环节 → 活性测试"的逐层排除法，比直接换件更快定位到"面包板 GND 轨断裂"这个真正根因。这也说明：传感器报"永远很湿"时不会产生任何误动作（安全方向正确），但系统缺少"读数零变化"告警——这是本次暴露的设计缺口。
