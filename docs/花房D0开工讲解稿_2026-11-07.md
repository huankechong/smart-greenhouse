## 第 1 段 · 项目原理（5 分钟）

### 1.1 一句话（30 秒）

> 一个会自己浇水的花盆：传感器发现土干了，就自动开水泵浇水；数据传上云，手机能看、能远程浇。

### 1.2 黑盒链路（2 分钟，边说边在白纸/白板上画）

```
4 个传感器 ──→ ESP32 大脑 ──→ 继电器 → 水泵
土壤·光照·温湿度·浮球   （固件判断）     （自动浇水，低水位断泵）
        │
        └──→ OLED 屏 + 双色灯（现场看）──→ 巴法云 MQTT（手机小程序远程）
```

要点：
- 传感器只负责**报数**，大脑负责**判断**，继电器就是个**电控开关**——开关一吸，泵就转。
- 双色灯：绿=土湿，红=土干，一眼看状态。

### 1.3 浇一次水的完整过程（2 分钟）——固件里真实的状态机

1. **读数**：土壤 raw 低于阈值 → 判定"干了"
2. **查水位**：浮球确认桶里有水——没水就报警、**绝不开泵**（干烧会烧泵）
3. **开泵**：继电器吸合，浇固定时长
4. **冷却**：等土里的水渗开再恢复判断——**防止刚浇完表还是干的假象，反复浇把盆泡烂**

> 为什么要讲冷却和查水位？这两条是硬件保护的核心，答辩也会问。谁问原理就指着实物讲。

### 1.4 器件传阅（1 分钟）

**动作**：把 **ESP32 板 → 继电器 → 水泵 → 土壤传感器 → 浮球** 依次传一圈，传到谁手里谁说出名字和它在上图的位置。传完顺势接下一句：

> 这些东西的"说明书"都在仓库里——接下来打开 GitHub 看看东西都在哪。

## 第 4 段 · 人人练提交：commit + PR（15 分钟，实操）

### 4.1 我先演示一遍（3 分钟）

**动作**：自己走完整流程——建文件 → 粘提示词 → Agent 跑 → 网页见 commit → 开 PR → 合并。

> 就这几步，以后每周都这么交。看我做一遍，然后你们自己来。

### 4.2 每人操作（12 分钟）

1. WorkBuddy 打开仓库文件夹，建自己的记录文件（照分工方案口径，文件名对应各自交付物）：R2 建 `docs/上云联调记录.md`、R3 建 `docs/打印日志.md`、R4 建 `docs/素材索引表.md`，各写两行字（今天开始记录什么 + 日期）
2. 把下面的提示词**原样粘给 WorkBuddy**——模板里的四个占位符先按下方对照表换成自己的（Mac 同学另看提示词里括号的差异说明）：

```text
请你检查这台电脑是否具备用 git 向 GitHub 提交代码的完整条件，缺什么就自己装/自己补，然后帮我把 <我的文件路径> 提交到 GitHub 并开 PR。

依次执行：
1. 查 Git：git --version，缺就 winget 安装（Mac 用 brew）。
2. 查身份：git config --global user.name / user.email，缺就问我，不要编造。
3. 查凭据：git ls-remote origin 试一次；不通就跑 git credential-manager github login 弹浏览器授权，不要让我贴 token（Mac 改走 gh auth login，见手册 §十一）。
4. 看状态：git status 先给我看，确认只提交我说的这一个文件。
5. 提交：先 git checkout main 并 git pull 到最新，再 git checkout -b <我的分支名>；然后 git add <我的文件路径>，git commit -m "docs: [<角色前缀>] <一句话说明>，D0 开工"，git push origin <我的分支名>。
6. 开 PR：push 成功后给我 <我的分支名> 分支的 Compare 链接，我在网页上开 PR（<我的分支名> → main）并合并。
7. 自检：跑 git log --oneline -3 把结果给我；失败把报错原文贴出来，最多重试 2 次。
```

**三个占位符对照表**（粘提示词前先替换，一人一份别照抄别人的）：

| 角色 | `<我的文件路径>` | `<我的分支名>` | `<角色前缀>` | `<一句话说明>` |
|---|---|---|---|---|
| R2 | `docs/上云联调记录.md` | `r2-cloud` | `[R2]` | 建上云联调记录 |
| R3 | `docs/打印日志.md` | `r3-print` | `[R3]` | 建打印日志 |
| R4 | `docs/素材索引表.md` | `r4-docs` | `[R4]` | 建素材索引表 |

3. push 成功后网页会出现 **Compare & pull request** 按钮，点开确认是自己的分支 → main、只含自己的一个文件，标题 `[Rn] + 一句话`（如 `[R2] 建上云联调记录`），我审查合并
4. **过关标准：网页上能看到你的文件 + PR 被合并**

> **MacBook 同学注意**：提示词第 1 步 `winget` 换成 `brew`；第 3 步凭据不用 GCM，改走手册 §十一的 `gh auth login`（浏览器授权后 gh 自动接管 git 凭据）。其余步骤完全一样。

### 4.3 三条红线（练的时候就守）

- 只提交**自己的文件**，不改别人的
- 提交信息带 `[Rn]` 前缀
- 不往仓库写学号/手机号/token

**出问题**：报错翻手册 §八「9 种常见报错速查」；Mac 翻 §十一；没连 GitHub 的当场连；10 分钟没通先换别人练，卡点记下来一起修。**今天通不了的，今天修到通，不留到下周。**

> 全过了顺势说：提交都通了，那把任务分了。

## 第 6 段 · 测元件开干（收尾 2 分钟 + 下午全场）

> 任务分完，直接开干。照《操作清单》的四步顺序来，顺序别打乱：

1. **继电器**（板上固件现成，听"咔哒"就过）——**接线图用 v2**：`docs/花房接线图_8.2水泵联调_v2_2026-11-07.html`（继电器是 JQC-3F 线圈 5VDC，**VCC 必接 ESP32 的 5V/VIN，接 3V3 吸不动**——这是按 11/06 借到实物修正过的）
2. **水泵**（量筒量水，记 ml/s 表）
3. **六项传感器逐个点亮**（一次只接一个，别全接上）
4. **浮球极性**（万用表蜂鸣档，10 分钟收尾）

**非主操两位**：轮流拍照录像（素材 ≥8 张）+ 记出水量表（几秒出多少 ml，这是固件浇水时长的依据）。

**收尾铁律**（离桌前）：借的器材清点还回；水擦干查滴水；照片传电脑备份——**微信 temp 会清理**，别存微信当唯一副本。

**最后再敲一次安全阀**：

> 土壤标定没做之前 `EN_WATER = 0`，自动浇水保持锁死。今天只验元件能动，不接自动流程。

**死线速览（口头带一遍）**：

- D0 今天：人人 commit+PR 合并 / 实验四件套 / 素材 ≥8 张
- D+1：我回填数据烧回主固件
- **D+2 周一上午：R3 交打印**
- D+3：R2 上云准备完成
- D+5：R4 报告大纲 + 电路图初稿
- D+6：土壤标定（测完才解锁自动浇水）
- 下周六上午：站会（R3 带取件时间，R4 带素材库初版）
