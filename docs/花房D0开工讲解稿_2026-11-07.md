## 第 1 段 · 项目原理（12 分钟）

### 1.1 一句话（1 分钟）

> 一个会自己浇水的花盆：传感器发现土干了，就自动开水泵浇水；数据传上云，手机能看、能远程浇。

**动作**：说完停 2 秒，环视一圈，确认没有一脸懵的，再往下。

### 1.2 黑盒链路（4 分钟，白纸/白板边画边讲）

**画图顺序**（画一笔讲一句，不要一次性画完整张图）：

1. 先画左边三个框：「**土壤湿度**（插土里的那根）」「**光照**」「**温湿度**」——这就是桌上传阅的三种传感器
2. 画箭头指向中间大框「**ESP32**」，说：

> 这块板子是大脑，里面跑着我写的程序，叫固件。它每隔几秒读一次三个传感器的数。

3. 画右边框「**继电器 → 水泵**」，说：

> 继电器就是个电控开关——大脑说"浇水"，它就吸合，泵就转；说"停"，它就断开。它俩今天下午第一个测。

4. 从 ESP32 往下画分支：「**OLED 屏**（现场看数据）」「**双色 LED**（绿=湿 红=干）」
5. 最后画出去的框：「**巴法云**（数据上云）→ **微信小程序**（手机远程看 + 远程浇水按钮）」

### 画完后的三句总结（对应三个角色，提前埋分工伏笔）

- 对应 R2 的：「数据怎么上云、小程序怎么控制，这块是**网络和云端**的活。」
- 对应 R3 的：「整机的结构件——桶盖、底盘、支架——是我们自己 3D 打印的，这是**结构**的活。」
- 对应 R4 的：「整个过程的记录、报告、答辩材料，这是**文档**的活。」

### 1.3 浇一次水的完整过程（4 分钟）——固件里真实的状态机

> 大脑不是"干了就浇"这么简单，它每次浇水要走四步，缺一步都会出事：

1. **读数**：土壤 raw 值低于阈值 → 判定"干了"
   - 补一句什么是 raw：「传感器输出的是一个数字，越干数字越大。阈值是多少要靠实测标定——这就是为什么自动浇水现在锁着。」（埋第 2 段伏笔）
2. **查水位**：浮球确认桶里有水——没水就报警、**绝不开泵**
   - 🎤：「为什么不直接浇？桶空了泵还在转，电机干烧几秒钟就废了。这是保护泵。」
3. **开泵**：继电器吸合，浇固定时长（几秒，具体几秒等今天量了出水量再定）
4. **冷却**：等土里的水渗开再恢复判断
   - 🎤：「为什么浇完不马上看？水刚浇下去，传感器附近的土还是干的，马上再看会以为没浇够，又浇一遍——反复几次盆就泡烂了。等它渗一会儿，是真湿了才认。」

**收尾一句**：

> 冷却和查水位这两条是硬件保护的核心，答辩评委大概率会问"你们怎么防止浇过头/烧泵"，答案就是这两条。谁记一下，答辩讲的时候用得上。

### 1.4 器件传阅（3 分钟）

**组织方式**：五件器件按顺序排成一排先展示——**ESP32 板 → 继电器 → 水泵 → 土壤传感器 → 浮球**，然后从右手边第一位开始传。

**规则说在传之前**：

> 传到谁手里，谁做两件事：说出它叫什么、说出它在上图哪个位置。说错不扣分，说不出来旁边的补。

**每件的提示**（谁卡住就提示）：

| 器件 | 期望答案 | 补充一句 |
|---|---|---|
| ESP32 板 | 大脑/主控，固件跑在里面 | 「翻过来看，背面有 WiFi 天线区域」 |
| 继电器 | 电控开关，控制泵的电源通断 | 「听到'咔哒'就是它在动作」 |
| 水泵 | 3W 小水泵，USB 供电，泡水里抽水 | 「待会儿它第一个出水」 |
| 土壤传感器 | 电容式，插土里读干湿（那根黑的） | 「它现在还没标定，所以浇水锁着」 |
| 浮球 | 水位开关，浮子随水面升降 | 「它决定泵敢不敢开」 |

传完顺势接下一句：

> 这些东西的"说明书"都在仓库里——接下来打开 GitHub 看看东西都在哪。

⚠️ **翻车点**：器件只有一套，传阅时提醒「轻拿轻放，土壤传感器探针别捏」；水泵传之前先擦干。

## 第 4 段 · 人人练提交：commit + PR（25 分钟，实操主战场）

### 4.1 我先演示一遍（5 分钟，边做边解说）

**动作与解说对照**（做一步说一句，让组员看到每步长什么样）：

1. **建文件**：「在 WorkBuddy 里让我建一个 `docs/上云联调记录.md`，里面写两行：今天开始记录什么 + 日期。就两行，写多了反而乱。」
2. **粘提示词**：「把提示词模板粘给它——模板里四个尖括号占位符要换成自己的，换法看对照表。」（投屏展示替换过程：指着 `<我的文件路径>` 说"这个换成 docs/上云联调记录.md"……四换四）
3. **Agent 跑**：「它会先查 Git、查身份、查凭据、看状态——**每一步都会把结果贴出来，你们看它贴了什么**。」
4. **看 commit**：「push 完它会给 git log，GitHub 网页刷新就能看到我的文件——注意现在是在我自己的分支上，不在 main 上。」
5. **开 PR**：「网页顶部会冒一个黄色条 **Compare & pull request**，点它 → 确认左边是你的分支、右边是 main → 填标题 → Create pull request。」
6. **合并**：「我看一眼没问题就点 **Merge pull request**——合并完你的分支上的文件就进 main 了，这就是'被合并的 PR'。」
7. **收尾话**：「就这几步，以后每周都这么交。看我做完了——现在轮到你们。」

### 4.2 每人操作（18 分钟）

**第 1 步 · 建文件（3 分钟）**

- 各自按角色建：R2 建 `docs/上云联调记录.md`、R3 建 `docs/打印日志.md`、R4 建 `docs/素材索引表.md`
- 内容就两行：第一行「# XX 记录」，第二行「2026-11-07 D0 开工，开始记录 XXX」
- **检查点**：走一圈看三人文件都建出来了、位置没建错（建到别的文件夹里的当场挪）

**第 2 步 · 替换占位符（2 分钟）**

把模板粘进 WorkBuddy 之前，先按自己的角色替换四个占位符：

| 角色 | `<我的文件路径>` | `<我的分支名>` | `<角色前缀>` | `<一句话说明>` |
|---|---|---|---|---|
| R2 | `docs/上云联调记录.md` | `r2-cloud` | `[R2]` | 建上云联调记录 |
| R3 | `docs/打印日志.md` | `r3-print` | `[R3]` | 建打印日志 |
| R4 | `docs/素材索引表.md` | `r4-docs` | `[R4]` | 建素材索引表 |

- **教替换方法**（有人不会用查找替换就手改）：「模板里所有尖括号连内容一起选中，删掉，填你的值。换完通读一遍，确认没有任何 `<>` 留着。」
- **检查点**：走一圈，让每人把替换完的提示词给你看一眼再粘——这里抓错比跑完再抓省 10 分钟。

**提示词模板**（替换完再粘）：

```text
请你检查这台电脑是否具备用 git 向 GitHub 提交代码的完整条件，缺什么就自己装/自己补，然后帮我把 <我的文件路径> 提交到 GitHub 并开 PR。

依次执行：
1. 查 Git：git --version，缺就 winget 安装（Mac 用 brew）。
2. 查身份：git config --global user.name / user.email，缺就问我，不要编造。
3. 查凭据：git ls-remote origin 试一次；不通就跑 git credential-manager github login 弹浏览器授权，不要让我贴 token（Mac 改走 gh auth login，见手册 §十一）。
4. 看状态：git status 先给我看，确认只提交我说的这一个文件。
5. 提交：先 git checkout main 并 git pull 到最新，再 git checkout -b <我的分支名>；然后 git add <我的文件路径>，git commit -m "docs: [<角色前缀>] <一句话说明>，D0 开工"，git push origin <我的分支名>。
6. 开 PR：push 成功后给我 <我的分支名> 分支的 Compare 链接，我在网页上开 PR（<我的分支名> → main）并合并。
7. 自检：跑 git log --oneline -3 把结果给我；失败把报错原文贴出来，最多重试 2 次。
```

> **MacBook 同学单独交底**（其他人跑的时候拉到一边说）：第 1 步装 Git 用 `brew install git`；第 3 步不用 credential-manager，直接 `gh auth login`（选 GitHub.com → HTTPS → Login with a web browser，抄一次性代码到浏览器）——详细步骤手册 §十一有截图级说明。其余步骤一字不差。

**第 3 步 · Agent 跑 + 网页开 PR（10 分钟，三人并行，你在中间转着看）**

- 每人粘提示词 → Agent 自己跑。**你巡场看三样**：
  - Agent 是否在 push 前**先贴了 git status 清单**（没贴就让它贴——铁律一）
  - 是否只 add 了**自己那一个文件**（add 了别人的立刻叫停 reset）
  - push 的分支名对不对（`r2-cloud`/`r3-print`/`r4-docs`，push 到 main 的立刻叫停）
- push 成功 → 网页黄色条 **Compare & pull request** → 点开核对三样：**base: main ← compare: 自己分支**、Files changed 只有 1 个文件、标题带 `[Rn]` → Create pull request
- 开完 PR 在群里喊一声（或在工位举手机），你过去看一眼点 **Merge pull request** → **Confirm merge**
- **过关标准：网页 main 分支上能看到他的文件 + PR 显示 Merged 紫色标**

**第 4 步 · 收尾确认（3 分钟）**

> 三个人都合并了的举下手。……好，从现在起你们都会交代码了。以后每周的活就按这个流程交：干完 → commit 到自己分支 → PR → 我合并。

### 4.3 三条红线（练的时候就守）

- 只提交**自己的文件**，不改别人的——git status 里出现别人的文件名，立刻停
- 提交信息带 `[Rn]` 前缀——没有前缀的 commit 我打回重写
- 不往仓库写学号/手机号/token——出现一个字我整个 revert

### 4.4 常见卡点与当场修法

| 卡点 | 现象 | 当场修法 |
|---|---|---|
| 没装 Git | `git --version` 报不是命令 | 让 Agent 跑 `winget install --id Git.Git -e`，装完**重开终端**再验 |
| 身份没配 | commit 报 `Author identity unknown` | 让 Agent 问你要 GitHub 用户名，配 global，**不要让它编** |
| 凭据不通 | push 卡住/报 403 | 跑 `git credential-manager github login`，浏览器里点授权；Mac 走 `gh auth login` |
| push 被拒 | `rejected (fetch first)` | 说明 main 有新提交，让 Agent 先 `git pull origin main` 再重试 |
| add 错文件 | git status 里出现别人的文件 | `git reset`（不带 --hard！）清掉暂存，重新只 add 自己的 |
| PR 开错方向 | base 不是 main | PR 页面 Edit 按钮改 base；或者关掉重开 |
| 10 分钟没通 | —— | 先换下一个人用这台机器练，卡点截图记下来，散会前集中修。**今天通不了的，今天修到通，不留到下周。** |

> 全过了顺势说：提交都通了，那把任务分了。
