## 一、背景：为什么临时加了本地记录

48h 测试原计划靠巴法云云端历史曲线，实际排查发现三道限制：

| 检查 | 结果 |
|---|---|
| `getmsg` API `num` 参数 | **只支持 num=1**（num=2/10/100/1000 全返回 0 条） |
| 控制台历史数据 | **需付费**（领导已付费，但 API 仍不给批量） |
| 常开采集电脑 | 无 |

→ 方案改为**设备端写 LittleFS CSV**（48h × 10s ≈ 17,280 行 ≈ 600KB，分区实测 1.375MB，占 43%）。
→ 本地记录不依赖网络、不依赖付费、不依赖电脑常开，且原始数据完全可控。

## 二、问题清单（按严重度）

### 🔴 严重（会导致 48h 数据报废）

| # | 问题 | 位置 | 成因 | 影响 | 处置 |
|---|---|---|---|---|---|
| P1 | `LittleFS.begin(true)` 挂载失败**自动格式化** | `logSetup()` | 参数 `true` = formatOnFail | 异常掉电后 FS 损坏 → 重启格式化 → **17,280 条全灭**，仅打印一行"挂载失败" | ✅ 改 `false` |
| P2 | `readStringUntil('\n')` 默认超时 **1000ms** | `loop()` 串口命令块 | Arduino 默认 timeout | 串口噪声但无换行 → 每次 loop 卡 1 秒 → **浇水 1 秒计时失准、水位消抖错乱** | ✅ `Serial.setTimeout(20)` |
| P3 | `sec` 列 `millis()/1000` 复位归零 | `logTick()` | 用相对时间 | 48h 内意外复位 → CSV 两段 sec 重叠，**时间轴无法还原** | ✅ 启动写 `#BOOT` 分隔标记 |

## 四、方法论沉淀

1. **两端点标定必须取"工作介质可达"的极值**：DRY 用真干土（1855）不用空气（2372），WET 用完全浸没（857）不用蘸水（1050）。取仪器极限会让整个映射区间被压缩，阈值判断系统性偏移——本项目 11-12 版就栽在这里，导致真干土显示 40% 永不浇水。
2. **审计要审"每次改动引入的新风险"**：P9/P11/P16/P21 全部是加本地记录模块时新引入的，原固件没有。
3. **条件编译块内的 include 是雷区**：功能代码用到某库时，include 必须在任何 `#if` 之外。
4. **阻塞式 IO 与实时状态机天然冲突**：串口读超时、Flash dump、`delay()` 采样，任何一处阻塞都会影响 1 秒级浇水计时。
