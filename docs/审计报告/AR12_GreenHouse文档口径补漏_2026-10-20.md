## 四、🔵 误判澄清：E 盘"缺 3 个文件"不成立

上一轮汇报（15:35）我写"E 盘镜像实缺 3 个文件：`.gitignore`、`outputs/花房3D_整机装配/交付说明_整机示意模型.md`、`outputs/花房代码/GreenHouse_v1/README.md`"，**这个结论是错的**。

- **错因**：E 盘镜像**不沿用 `outputs/` 目录名**，而是按人类可读名分桶——`3D打印件/`、`代码/`、`docs/`、`素材/`、`邮件/`。我拿仓库相对路径 `outputs/...` 去 E 盘拼接，必然 `[ -e ]` 为假，于是三个文件全被判"缺失"。**这是路径假设错，不是文件缺失。**
- **实测复核**（22 份关键文件逐个 `md5sum` 本地 vs E 盘）：

| 组 | 文件数 | 结果 |
|---|---|---|
| 3D 整机装配交付说明 | 1 | md5 一致 ✅ |
| 固件 `GreenHouse_v1`（.ino / README / config.h） | 3 | README、config.h 一致 ✅；**`.ino` 行尾不同**（见下） |
| 根文档（README.md / AGENTS.md） | 2 | 一致 ✅ |
| `docs/` 七份主题文档 | 7 | 一致 ✅ |
| `docs/审计报告/` AR02–AR11 | 10 | 一致 ✅ |
| **合计** | **23**（含 .ino） | **22 一致 + 1 行尾差异** |

- **`.ino` 行尾差异**：本地 24,773 B（CRLF）、E 盘 24,258 B（LF），差 515 字节；`tr -d '\r'` 后两边 md5 **同为 `4adeceffc0a4ddbcea549603798b5ea9`**，即**内容逐字节相同，仅行尾风格不同**。这与 AR11 记录的"归一化后 md5 4adeceff"完全吻合——E 盘那份是归一化（LF）产物，本地是编辑器保存的 CRLF 版。**无需处理**：Arduino 编译器两者等价，git 也按 LF 存储（`git hash-object` = `f75b7b84…`）。
- **`.gitignore`**：E 盘镜像不是 git 仓库，本就不需要该文件，**不算缺失**（不补）。

**教训（已写进本报告，供下次自查）**：核对镜像不得默认目录名与仓库一致——**先 `ls` 目标根目录确认真实分桶名，再拼路径**；判断"缺失/不一致"前必须做 md5 或去行尾比对的**内容级校验**，不能只靠 `[ -e ]`。

## 六、已知限制与建议

1. **预算区间不是精确值**：清单里 6 项写的是"参考价区间"（如 5–8 元），实际以订单为准。**建议**：答辩前把淘宝订单实付逐笔填进清单 2.2，把区间收成单一数字，报告里就能写"实付 XX 元"。
2. **WAGO 端子数量未定**：按 1 个计（±2–5 元）。若按接线表需要 412 二线位 + 413 三线位各 1 个，应改为 2 个，届时上限 +5 元。
3. **金额口径没有单一真相源**：清单 2.2 是加总依据，交接文档只是引用。**再改采购必须改清单、再同步引用**——这条已写进 §一 的括号里，减少下次漏改。
4. **E 盘镜像没有自动校验脚本**：本次是手工 md5。**建议**（可选）：把 `ar12_fix.py` 同目录放一个 `check_mirror.py`，一键比对本地↔E 盘全部 md，省得每次靠记忆拼路径。本次未做，等领导裁定。
5. **★ 提交撞车留档（重要）**：本轮改动落盘并读回验证后，**被并行流程的 `efaf431`（提交信息为"云端清空状态确认：销账最后一条残留"）一并提交并推送**——该提交信息只描述云端清空与 AR11 第 7 条补记，实际 diff 里夹带了本轮 AR12 的全部 7 个文件（AGENTS.md / index.md / AR11 / AR12 新报告 / 借用清单 / 交接文档 / 迁移包，+164/−10）。**提交信息与实际内容不符**，日后追溯 AR12 会找不到对应 commit message。
   - 处置：不擅自改写他人已 push 的历史（不 rebase / 不 amend）；改为在本报告留档说明，**AR12 的实际落盘凭据 = `efaf431` 这笔提交**。
   - 二次修正（22/23 统计口径统一、U+200B 零宽字符清理）在本报告写下时仍在工作区未提交，**等领导裁定后单独补一笔**，提交信息会写明 AR12 追加修正。
   - 教训：**多会话并行时，任何 `git add -A` / `git commit -a` 都会把别人的半成品一起卷进去**。以后提交前必须先 `git status` 核对文件清单，只 `git add <精确路径>`。
