## 二、已修复问题明细

### 🔴 高危 1 项

**A-1 `gSoilPct > 0` 哨兵判断是真实逻辑缺陷**
- **位置**：v1.0 L120（updateStatusLed）、L129（waterTick 触发）
- **成因**：用 0 当"无数据"哨兵，但 0% 是合法湿度（极干土实测完全可能）
- **影响**：土壤真到 0% 时红灯不亮、该浇不浇——答辩演示"极干土壤触发浇水"核心场景可能踩中
- **修复**：新增 `bool gSensorReady`，`setup()` 末尾首次 `readSensors()` 后置 true；两处判断统一为 `gSensorReady && gSoilPct < SOIL_THRESHOLD_PCT`（L91、L134、L151、L278）

### 🟡 中危 2 项

**A-2 WiFi 掉线后永不重连**
- **位置**：v1.0 setup() L226-236 vs loop() L252
- **影响**：路由器重启/热点掉线后云功能永久失效，需手动复位——现场演示真实风险
- **修复**：loop() 头部加 30s 间隔重连块（`WiFi.disconnect()` + `WiFi.reconnect()`），计时器 `lastWifiRetry`（L52、L58、L284-290）

**A-3 WiFi 密码/巴法云 UID 明文硬编码**
- **位置**：v1.0 L46-47、L53
- **影响**：代码分享/传 GitHub/交报告时凭据泄露，UID 泄露＝任何人可远程控制浇水
- **修复**：凭据抽入新建的 `config.h`（含 `#pragma once` + 分享前脱敏警示），主程序 `#include "config.h"`。**注意：config.h 是唯一存真值的地方，外发版需改回 `<...>` 占位符**（L55-59、L60-62）

## 三、编译验证（双形态取证）

| 形态 | 结果 | Flash 占用 | RAM 占用 |
|---|---|---|---|
| 全关（交付态，6 开关=0） | ✅ PASS | 269,477 字节（20%） | 21,592 字节（6%） |
| 全开（6 开关=1，临时验证态） | ✅ PASS | 900,305 字节（68%） | 47,000 字节（14%） |

验证方法：arduino-cli 0.35 离线编译，fqbn `esp32:esp32:esp32`，esp32:esp32@2.0.17。与 v1.0 对比：全关 +72 字节、全开 +164 字节（v1.0 为 269,405 / 900,141），开销全部来自新增的防呆/重连/非阻塞逻辑，属预期增长。全开验证完成后已将开关恢复为全 0 并 grep 核对。

**编译排障插曲（记入 W3 上云阶段的知识）**：全开首次编译被超时中断（SIGTERM）后，默认构建缓存损坏，重试报 `WiFi.h: No such file or directory`（verbose 显示一条库 `-I` 路径都没有）。用最小 WiFi sketch 证明环境本身正常，**改用 `--build-path` 指定全新目录绕开坏缓存后一次通过**。教训：编译被强杀后若报缺头文件，先换 `--build-path` 干净目录再怀疑代码。

## 三·补、行为级验证清单（到货后照做）

编译通过 ≠ 行为正确。以下场景需硬件到货后实测：

1. **0% 边界**：探针悬空（读数应顶到干点附近）→ 红灯亮、触发自动浇水（v1.1 修复的直接验证）
2. **远程浇水非阻塞**：手机发 on → 5s 内 OLED 照常刷新、Web 页照常打开
3. **WiFi 重连**：路由器断电 10s 再上电 → 串口应出现"[WiFi] 掉线，尝试重连..."并恢复上报
4. **标定防呆**：故意把 DRY/WET 填反 → 启动串口出现自检失败提示
5. **`msg == "on"` 精确匹配**：巴法云发 `on\r\n`（带换行）→ 仍能触发（trim 兜底）
6. **relay 极性**：`RELAY_ACTIVE_HIGH` 翻转 → 串口日志正确反映吸合/断开
7. **49.7 天回绕**：无需实测，逻辑上 millis() 差值无符号减法天然安全（报告可写）
