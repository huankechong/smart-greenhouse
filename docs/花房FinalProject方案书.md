## 一、选题陈述（答辩开场用）

**项目名称**：智能花房养护站 Smart GreenHouse  
**技术定位**：嵌入式物联网系统（嵌入式 MCU 开发 + 云端联动）——ESP32 是单片机（MCU），固件直接跑在硬件上，符合嵌入式系统"专用功能、软硬件一体、资源受限"的定义；这也是它与树莓派方案的本质区别（树莓派是跑 Linux 的微型计算机，ESP32 才是嵌入式 MCU）。  
**一句话介绍**：面向家庭养花"浇水靠感觉、出门没人管"的痛点，用 ESP32 构建一套"感知 — 决策 — 执行 — 上云"完整闭环的桌面智能养护系统。

**为什么选这个题**（答辩叙事主线）：

1. **真实需求**：家里自营花店、自采花材，浇水量与光照是日常真实痛点——项目源于生活，不是为做而做；
2. **问题可分解**：正好用课程教的"复杂问题分解法"，拆成感知/执行/上云三个模块逐个击破；
3. **技术选型有故事**：课上 Arduino UNO 有 WiFi → 对比 UNO/ESP32/树莓派三平台 → 选 ESP32，完整的工程决策过程；
4. **课堂知识闭环**：10/17 实验课学的双色 LED 直接用作系统状态指示灯，Fritzing 画全部电路图。

## 二、系统架构（感知 / 执行 / 上云三大模块，决策逻辑内嵌于 ESP32）

```
┌───────────────────────────────────────────────┐
│                感知层（输入）                │
│ 土壤湿度（电容式）、DHT11 温湿度、光敏电阻       │
└───────────────────────────┬───────────────────┘
                            │ 模拟 / 数字信号
                            ▼
┌───────────────────────────────────────────────┐
│            ESP32 主控（决策核心）            │
│ 阈值判断、自动浇水逻辑、OLED 本地显示           │
└───────────────────────────┬───────────────────┘
                            │ 继电器 / GPIO 控制
                            ▼
┌───────────────────────────────────────────────┐
│                执行层（输出）                │
│ 继电器 + USB 水泵（自动浇水）                 │
│ 双色 LED 状态灯（绿=正常  红=缺水）            │
└───────────────────────────┬───────────────────┘
                            │ 数据上行 / 指令下行（WiFi / MQTT）
                            ▼
┌───────────────────────────────────────────────┐
│        云端层：巴法云 bemfa.com:9501         │
│ 微信小程序：实时数据、历史曲线、远程浇水         │
│ 保底：局域网本地网页（断网兜底）                │
└───────────────────────────────────────────────┘
```

**模块化容错设计**：感知/执行/上云三块相互独立，任何一块故障均可降级演示（如断网走局域网页面、水泵故障换手动），显著降低现场演示风险。

## 五、答辩加分点清单

1. **每件传感器都有明确职责**（评委必问"为什么用 X"）：土壤湿度 → 整个系统唯一的浇水闭环触发源，直接测量根系实际供水，是"主角传感器"；光敏电阻 → 光照是光合作用的能量来源，只看湿度是"防渴死"，加上光照才能回答"长得好不好"；温湿度 → 蒸腾作用强度与病害（高温高湿易真菌）风险。答不上"为什么用"等于承认自己只是照抄教程。
2. **自建模加分**：SolidWorks 全过程截图写进报告（课程明确说了这是加分项）
3. **问题分解法**：PPT 专设一页展示感知/执行/上云的分解逻辑，呼应课堂内容
4. **失败与排查页**：如实记录调试问题（如土壤传感器读数漂移、MQTT 连接失败排查），工程素养的直接证据
5. **选型决策表**：UNO vs ESP32 vs 树莓派对比表，展示技术决策能力
6. **数据证据**：48h 连续运行的云端历史曲线 = 系统可靠性的实证
7. **故事线**：花店家庭背景 → 真实需求 → 课堂双色 LED 复用 → 项目落地，情感与逻辑双闭环

> **加分项数据支撑提醒**：巴法云免费版历史数据保留期有限，Week 3 上云成功当天就导出/截图存档，Week 4 的 48h 曲线跑完立即再导一次——报告里的数据证据宁可多存不可临期补抓。
