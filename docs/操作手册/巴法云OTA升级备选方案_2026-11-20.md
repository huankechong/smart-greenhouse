## 一、机制说明（与 ArduinoOTA 的区别）

| 项 | ArduinoOTA | **巴法云 OTA** |
|---|---|---|
| 原理 | 局域网内 ESP32 自己开端口接收固件 | **巴法云当固件 CDN**，设备 HTTP 拉 .bin |
| 网络要求 | 同一局域网 | 只要设备能上网（跨网段也行） |
| 触发 | IDE 点按钮 | **设备自己决定**（代码里写逻辑） |
| 地址 | 每次编译变 | **固定地址**，重传新版本地址不变 |

**关键认知**：巴法云不会主动推"去升级"的指令。设备侧必须有触发逻辑——本项目采用 **MQTT 下行指令触发**（复用现有 `4QT4BZIBM001` 通道）。

## 二、操作步骤

### 第 1 步：上传固件到巴法云（控制台，2 分钟）

1. 登录巴法云控制台 → 找一个主题（或新建，如 `ota001`）
2. 点该主题的 **OTA** 按钮
3. 点「上传固件」→ 选 `D:/tb_xxx/GreenHouse_v1.ino.bin`
4. 上传成功后**复制固件地址**（形如 `http://bin.bemfa.com/b/xxxxxxxx`）
5. 该地址固定，后续重传新版本**地址不变** → 只需改代码里的 URL 一次

### 第 2 步：改代码（3 处，约 15 行）

**① 头部加 include**

```cpp
#include <HTTPUpdate.h>   // 巴法云 OTA：HTTP 拉取 .bin 自刷
```

**② config.h 加速常量**（不要硬编码在 .ino 里）

```cpp
const char* OTA_URL = "<粘贴巴法云 OTA 固件地址>";
```

**③ 加升级函数 + MQTT 指令分支**

```cpp
// ---- 巴法云 OTA：收到 ota 指令后拉取固件升级 ----
void doOTA() {
  Serial.println("[OTA] 开始拉取固件...");
  WiFiClient otaClient;                      // 独立 client，不复用 mqtt 的
  t_httpUpdate_return ret = httpUpdate.update(otaClient, OTA_URL);
  switch (ret) {
    case HTTP_UPDATE_FAILED:
      Serial.printf("[OTA] 失败 (err=%d): %s\n",
                    httpUpdate.getLastError(),
                    httpUpdate.getLastErrorString().c_str());
      break;
    case HTTP_UPDATE_NO_UPDATES:
      Serial.println("[OTA] 服务器上无固件");
      break;
    case HTTP_UPDATE_OK:
      Serial.println("[OTA] 成功，即将重启");   // 成功后自动重启，此处通常来不及打印完
      break;
  }
}
```

在 `mqttCallback()` 里，`on` 分支旁边加：

```cpp
  else if (String(topic) == TOPIC_CMD && msg == "ota") {

    delay(200);
```

## 三、风险与回滚

| 风险 | 说明 | 应对 |
|---|---|---|
| 升级中断电/断网 | ESP32 双分区机制会自动回滚到上一版，**不会变砖** | 升级时别动电源 |
| 升级后功能异常 | 新固件可能引入 bug | 保留上一版 .bin，USB 重烧即可退回 |
| 体积超限 | 现在 85%，加 OTA 预计 88–90% | 编译输出超 95% 就放弃 |
| 数据中断 | 升级必然重启，48h 计时清零 | **只在停机后做**，绝不在测试期间 |
