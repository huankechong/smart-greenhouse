# 智能花房 · 4 人小组分工方案

> 定稿 2026-10-20 · 适用期 10/20 → 11/16 答辩
> 配套：《花房30天执行计划.md》（原始单人排期，本文按人重排）《花房接线规划表.md》《W1到货点火与标定操作指南_2026-10-20.md》

---

## 一、一句话结论

**领导（刘俊博）当系统负责人，抓固件 + 集成 + 答辩；另外三人一人一块「结构打印」、一块「上云数据」、一块「文档影像」，三块互不重叠、各自可独立验收——技术主干不摊薄，风险不集中。**

| 角色 | 代号 | 主责 | 每周投入 |
|---|---|---|---|
| 系统负责人 | **R1** 领导 | 固件 / 集成 / 标定 / 答辩主答 | 4 h |
| 上云与数据 | **R2** 编程强的组员 | MQTT / 小程序 / 数据证据 / 固件副手 | 3 h |
| 结构与打印 | **R3** 会 CAD 的组员 | 切片 / 机时 / 打印 / 试装 / 偏差回填 | 3 h |
| 文档与影像 | **R4** 文笔强的组员 | 素材库 / Fritzing / 报告 / PPT / 视频 | 3 h |

> 合计约 13 h/周、四周约 52 h 人力，对剩余工作量（约 30–35 h）留有冗余。

---

## 二、为什么这么切（三条原则）

1. **按"交付物"切，不按"工序"切。** 每人手里都有一份能单独交出去的东西（打印件 / 云端数据 / 报告 PPT），不出现"我干了一半等别人"的悬空状态。
2. **技术主干不外放，但也不做单点。** 固件与几何脚本只有 R1 能改（参数化脚本、AR 系列审计都是他建的），但 R2 必须能接手烧录与上云联调，R3 必须会改 `PARAMS` 重跑脚本——**领导一旦请假，项目不能停**。
3. **硬件活必须凑同一时段块。** 器件不可带离实验室，所以 W1/W2 的实验室任务尽量四个人同一时段进，一次把接线、拍摄、焊接、试装全做完，减少往返。

## 三、角色卡（职责 / 交付物 / 验收标准）

### R1 · 系统负责人（领导）

- **职责**：固件唯一修改人；6 个尺寸标定与参数回填；整机集成联调；48h 测试排障；答辩技术问答主答。
- **交付物**：`config.h` 标定值回写完成的主程序、集成联调记录、48h 运行日志、答辩小抄。
- **验收**：拔插探针能触发/停止浇水；低水位能断泵；小程序能看数能下指令。
- **工时分布**：W1 最重（点火 + 标定，约 8 h），W2 中等，W3 轻，W4 回升。

### R2 · 上云与数据（编程强的组员）

- **职责**：巴法云双主题复核、小程序绑定、MQTT 上行与远程浇水下行联调、局域网保底页、**所有云端数据证据的导出与归档**。
- **交付物**：小程序实时面板截图、远程浇水录屏、首批历史曲线、48h 曲线图、局域网页面截图。
- **验收**：手机点按钮 → 水泵出水（视频为证）；历史数据在免费保留期内当天导出。
- **关键提醒**：巴法云免费版历史数据保留期有限，**上云成功当天就导**，不许拖到 W4 补抓。

### R3 · 结构与打印（会 CAD 的组员）

- **职责**：切片、机时、打印盯机与取件、试装偏差记录与回填；**兼物料采购**（杜邦线/面包板/带针模块等小件当天补）。
- **交付物**：打印日志（件号/耗时/耗材/失败重打）、10 件实体、试装偏差表、补打清单。
- **验收**：10 件全部打印完成且能互装；06c 连接块 M3 自攻咬合手感确认。
- **红线**：**不许手改 STL**。改尺寸只改脚本顶部 `PARAMS`，由 R1 复核后重跑。

### R4 · 文档与影像（文笔强的组员）

- **职责**：素材库（命名 `W{周}-{任务号}`）、全程拍照录屏、Fritzing 整机电路图、报告撰写与图文比控制（≥6:4）、PPT 8–10 页、兜底视频剪辑。
- **交付物**：素材索引表、电路图 PNG、报告初稿/二稿、PPT 终稿、3 分钟兜底 mp4。
- **验收**：报告按课程模板结构齐全（背景→选型→三模块→失败排查→48h 数据→安全考量→总结）；PPT 每页一图。
- **关键提醒**：素材当场拍当场归档，**事后补拍的照片一眼假**，答辩照片的真实性是隐性评分点。

## 五、三处排期修正（相对原 30 天计划）

1. **真正的关键路径是打印，不是标定。** 打印 20.5 h 机时 + 两片底盘各 6 h 排队，**11/5 是全项目最硬的死线**；标定最晚 10/30 做完即可。所以 **10/26 就开打**（用现有 v1 STL，尺寸本就是市售占位值），标定完只补打偏差件，不重打全套——早开打一周，等于多一整轮重打窗口。
2. **W1 的硬节点是"补料"，不是"标定"。** 杜邦线/面包板/带针模块借不到（约 15–25 元方案 E），料不到，标定和点灯全卡住。10/21 下单、2–3 天到货，正好接上 W1 剩余时间。
3. **不等料的活先做。** R1 转去核对丝印与接线表、R2 做上云准备、R4 建素材库与报告大纲、R3 推进切片与机时——四个人的 W1 都不该空转。

## 六、协作机制（4 条，不多）

1. **周日 20:00 站会 30 分钟**：每人 2 分钟 —— 本周交付了什么 / 下周要谁配合 / 卡在哪。不写会议纪要，只在群里回一句"我卡在 X"。
2. **留痕**：所有文件改动走 git，commit 前缀标角色 `[R1]`…`[R4]`；素材命名 `W{周}-{任务号}-{描述}`。即使课程不查贡献度，答辩被问"这块谁做的"时能秒答。
3. **单一真相源**：文档只认 `docs/`，实物只认项目文件夹 `3D打印件/`、`代码/`；不许各自存一份"我的最终版"。
4. **谁都不能让项目停**：R1 请假 → R2 顶上烧录联调；R3 请假 → R1 自己切片打印；R4 请假 → 报告进度最危险，其他人轮流填素材。

## 七、风险与缓解

| 风险 | 概率 | 缓解 |
|---|---|---|
| 组员对"花房已完成大半"有落差，觉得自己是来打杂的 | 中 | 站会上讲清每人产出都是报告/PPT 里独立署名的一节或一页，不是杂活 |
| **物料/工具借不到**（杜邦线、面包板、电烙铁、万用表，10/20 已实际发生） | **高（已发生）** | R3 立刻执行方案 E 自购 15–25 元；同时 R1 走"无烙铁接线方案"绕开焊接 |
| 硬件到货晚于 10/22 | 中 | W1 的纯软件项（R2 上云准备、R3 切片、R4 报告大纲）先做，实物任务顺延不压缩 W2 |
| 打印排队 / 首版偏差大 | 中 | 10/26 开打 + 只补打偏差件 + 预留 11/5 前重打窗口 |
| 上云在校园网连不上 | 中-高 | 直接用手机 2.4 GHz 热点（ESP32 不支持 5 GHz），第一天先验证 WiFi 再调 MQTT |
| 巴法云免费版历史数据过期 | 中 | 上云当天导一次、48h 跑完立刻再导一次，R2 负责 |
| 四人时间凑不到同一实验室时段 | 中-高 | 每周固定锁一个半天（建议周三晚或周六上午），实验室任务集中在该块内 |

## 八、已确认前提（2026-10-20）

1. **课程允许 4 人共做一份**，共同答辩、按同一份最终成果评分——不存在"个人提交"的冲突，本方案可直接执行。
2. **组员具体是谁不影响分工结构**：R2/R3/R4 三顶帽子按实际强项对号入座即可，任务矩阵与 DDL 一律不变。
3. 因此本方案取代 `docs/花房FinalProject方案书.md` 与 `docs/花房30天执行计划.md` 中"期末个人项目"的表述（两份文档头部已同步改口径），**但单人排期的任务内容仍然有效**——分工方案只是把这些任务按人重排了一遍。
