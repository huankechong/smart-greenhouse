## 一、一句话结论

**领导（刘俊博）当系统负责人，抓固件 + 集成 + 答辩；另外三人一人一块「上云数据」、一块「结构打印」、一块「文档影像」，三块互不重叠、各自可独立验收——10/20 定的角色结构原封不动，v2 重排的只是时间轴（W1–W4 → S1–S4 相对排期）。**

| 角色 | 代号 | 主责 | 每周投入 |
|---|---|---|---|
| 系统负责人 | **R1** 领导 | 固件 / 集成 / 标定 / 答辩主答 | 4 h |
| 上云与数据 | **R2** 编程强的组员 | MQTT / 小程序 / 数据证据 / 固件副手 | 3 h |
| 结构与打印 | **R3** 会 CAD 的组员 | 机时 / 打印 / 试装 / 偏差回填 | 3 h |
| 文档与影像 | **R4** 文笔强的组员 | 素材库 / Fritzing / 报告 / PPT / 视频 | 3 h |

> 合计约 13 h/周。剩余工作量约 25–30 h（标定/打印/集成/写作），人力仍有冗余；组员从 D0 才开始投入，R1 此前已垫付大量基础工作（见 §五 已完成账）。

## 三、为什么这么切（三条原则）

1. **按"交付物"切，不按"工序"切。** 每人手里都有一份能单独交出去的东西（云端数据 / 打印件 / 报告 PPT），不出现"我干了一半等别人"的悬空状态。
2. **技术主干不外放，但也不做单点。** 固件与几何脚本只有 R1 能改（参数化脚本、AR 系列审计都是他建的），但 R2 必须能接手烧录与上云联调，R3 必须会改 `PARAMS` 重跑脚本——**领导一旦请假，项目不能停**。
3. **硬件活锁定两个时段块。** 器材已借出到宿舍：**D0（周六）宿舍电子日**做全部桌面实验；**D+2（周一）实验室日**交打印、盯机、试装。两次集中干完，减少往返。

## 八、协作机制（4 条，不多）

1. **站会：每周六上午，30 分钟**（首个 = D0 开工对号会）。每人 2 分钟：本周交付了什么 / 下周要谁配合 / 卡在哪。不写纪要，群里回一句"我卡在 X"即可。
2. **留痕**：走 Git 的 commit 前缀 `[R1]`…`[R4]`；走连接器的在 PR 标题带同样前缀；素材命名 `S{阶段}-{任务号}-{描述}`。答辩被问"这块谁做的"时能秒答。
3. **单一真相源**：文档只认 `docs/`，实物只认 `3D打印件/`、`代码/`；不许各自存"我的最终版"。
4. **谁都不能让项目停**：R1 请假 → R2 顶烧录联调；R3 请假 → R1 自己切片打印；R4 请假 → 报告最危险，其他人轮流填素材。
